# Phase 9F — Clients, Testimonials, and Statistics

## Objective and audit findings
Phase 9F adds three canonical CMS content types without CRM, analytics, review aggregation, or fabricated trust content. Phase 8 stores clients, testimonials, and statistics as typed `homepage_items`, preserving fallback title, description/quote, organization, local image, URL, rating, value, prefix, and suffix. `HomepageViewData` already maps bounded active items into public-safe arrays and previously resolved Solution, Product, Industry, Capability, and Work Process canonical records only when public.

The Phase 9A–9E pattern is Eloquent models with `publiclyVisible`, managers for transactional lifecycle/order, dependency inspectors, bounded relation managers, public-safe view-data, version-key caches, controllers, Form Requests, Blade views, factories, and Pest feature tests. `PublicAssetPath` permits relative raster assets beneath `storage/`, `images/`, or `assets/`, rejecting SVG, schemes, traversal, backslashes, and absolute paths. `PublicLink` permits safe relative or HTTP/HTTPS destinations without credentials. Admin routes share auth, active-administrator, installed-state, CSRF, and throttling middleware. Previews are protected, bypass public cache, and send no-store/noindex headers. Sitemap entries are explicit and lifecycle filtered. Navigation relational targets resolve their current slug and become disabled when private.

No standalone canonical Client or Testimonial model existed before this phase; only homepage preview concepts existed. Automatic matching was rejected: names, quotes, and values are not stable identifiers and could create duplicates or attach claims to the wrong organization. Fabricated clients/logos/testimonials/statistics create legal, reputational, accessibility, and consumer-trust risks. Unpublished testimonials can disclose unapproved statements; invalid logos can imply endorsement; transformed statistics can mislead. Accordingly, all records are administrator-entered, empty by default, and never seeded. The Client domain is deliberately organization content—not contacts, purchases, projects, leads, opportunities, invoices, authentication, or portals.

## Architecture and schema
`clients` stores name/slug, explicit allow-listed type, plain-text description, safe local logo and required alt, safe website URL, ISO-style country code, optional restrictive Industry FK, lifecycle/order/feature fields, basic metadata/robots, and nullable audit users. Full `/clients` index and `/clients/{slug}` detail routes were selected because description, industry, logo, website and bounded public relations provide useful structured detail content. Client relations are restrictive pivots to Solutions (8), Products (8), Capabilities (8), and Pages (6); duplication intentionally does not copy them or Industry.

`testimonials` stores optional Client, person, designation, fallback organization, bounded plain-text quote, optional safe local image/alt, nullable integer rating 1–5, optional safe source URL, lifecycle/order/feature, and audit users. `/testimonials` is a listing only: individual testimonial URLs add no semantic value. Canonical Client name overrides fallback only when the Client is public. No sample content, inferred rating, source import, HTML/Markdown rendering, or Review JSON-LD exists.

`statistics` stores label and exact string value, optional prefix/suffix/description, allow-listed group, controlled icon token, optional source note/URL/date, lifecycle/order/feature, and audit users. Statistics are reusable canonical payloads, not analytics. There is intentionally no `/statistics` route: an isolated metrics directory is not useful in the current information architecture. Rendering concatenates only the explicitly stored prefix, value, and suffix; it performs no arithmetic, percentage formatting, plus-sign insertion, or animation.

## Lifecycle, scheduling, preview, and dependencies
Save creates or updates draft content without publication. Publish requires core content, timestamps `published_at`, and clears scheduling/archive state. Schedule interprets the Website Setting timezone and stores UTC. Only due published or due scheduled, non-archived records are visible. Unpublish preserves content as draft; restore returns archived content to draft. Duplicate resets lifecycle and audit linkage; Testimonial duplication omits Client, Client duplication omits canonical relations, and Statistic copies are labelled for administrator verification.

Client and Testimonial previews use public presentation with a Preview Mode banner; Statistic preview is a protected component page. All emit private no-store and noindex/nofollow headers. Client archive is blocked by active homepage items, navigation items, or public testimonials. Testimonial and Statistic archive are blocked by active homepage references. Restrictive foreign keys provide a second integrity boundary.

## Homepage canonical migration and navigation
Nullable restrictive `client_id`, `testimonial_id`, and `statistic_id` columns were added to `homepage_items`; no data is matched or backfilled. Existing Phase 8 fields remain fallbacks. A canonical record overrides only its own safe fields while publicly visible; a private reference never leaks and the fallback remains usable. Model observers bump focused versions and invalidate Homepage cache only when the changed record is referenced.

Clients add the relational `client` navigation type. Only non-archived Clients are selectable; runtime links require public visibility and resolve the current slug, otherwise the item is disabled. Archive inspection protects active navigation dependencies. Testimonials use the approved `testimonials.index` route. Statistics add no navigation type.

## Caching, sitemap, queries, and structured data
Clients use versioned index and per-record caches; Testimonials use a versioned listing cache; Statistics use a versioned reusable payload. Keys include a minute boundary so newly due schedules cannot remain stale. Cache failures fall back safely, and no global flush occurs. View-data eagerly loads relations and applies explicit limits; Blade performs no database queries.

The sitemap includes `/clients`, visible/indexable Client details, and `/testimonials`; it excludes private, future, archived, noindex, preview, and admin content. There are no testimonial detail or Statistics entries. Client pages use WebPage/breadcrumb semantics from public chrome; Organization JSON-LD is not emitted because available fields may not establish a complete organization identity. Review schema is disabled by default. Statistics have no special schema. Administrator JSON-LD is never accepted.

## Security, accessibility, and performance
All input is escaped plain text; arbitrary HTML, Blade, PHP, JavaScript, CSS, iframes, SVG, embeds, remote images, and arbitrary JSON-LD are unsupported. Explicit fillable fields, allow-lists, safe URLs/assets, relation bounds, lifecycle scopes, CSRF and existing middleware protect the modules. No external calls, licensing resolution, secrets, roles, permissions, registration, CRM, analytics, or portal behavior was added.

Client cards provide logo alt or a text fallback, semantic headings and keyboard links. Testimonials use `blockquote`/`figcaption` and textual “out of 5” ratings. Statistics expose visible label/value without animation or color-only meaning. Admin forms use labelled existing components, responsive grids/tables, and existing focus styles. Public output is server-rendered Blade with bounded eager loads and no new JavaScript, fonts, dependencies, or remote APIs.

Run `php artisan optimize:clear`, `php artisan migrate`, `vendor/bin/pint --dirty --format agent`, `php artisan route:list --except-vendor`, the focused `php artisan test --compact tests/Feature/Clients`, `tests/Feature/Testimonials`, and `tests/Feature/Statistics` suites, then all requested regression suites and `php artisan test`. Run `npm run build`, `php artisan config:cache`, `php artisan route:cache`, `php artisan view:cache`, and finally `php artisan optimize:clear`. Dependency installation commands are listed by the delivery environment but must not update committed lockfiles.

## Manual acceptance
Create only a legitimate Client, test its local raster logo/alt, optional Industry and safe URL, then exercise draft, preview, publish, due scheduling, unpublish, dependency-aware archive, restore, duplicate, Homepage reference, navigation reference, and cache/sitemap behavior. Enter a genuine testimonial, optionally associate a Client and rating, verify semantic quotation output and no generated content/Review schema, then exercise its lifecycle and Homepage dependency. Enter a truthful statistic, verify exact prefix/value/suffix plus optional source/date, exercise lifecycle/Homepage dependency, and confirm no formatting or counter animation. At 200% zoom and by keyboard, inspect responsive admin/public layouts. Regress all Phase 1–9E areas, registration lock, installer, licensing, production caches/build, and recent logs.

## Known limitations and Phase 10 handoff
Client highlights were not introduced because current structured fields and bounded relations support meaningful detail without drifting into case studies. Testimonial source URLs remain stored but are not automatically displayed. Statistics intentionally have no public index. Runtime migrations, route/config/view caches, full Pest regression, and production Vite build require local dependencies and database validation.

Phase 10 may add Insights/Articles, Article Categories, Case Studies, and FAQs. Phase 9F creates none of those modules and does not pre-empt their schema or relationships.
